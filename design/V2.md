# Merged v2: open PRs, streak + goal, badges, cat colony, week recap, cleaner lines, smart polling, buzz

Picked by the user on 2026-10-26 from a list of 10 ideas (not picked: reviews-given counter, heatmap).
Each new thing that is a collection or a scene gets **its own swipeable screen**; Today is unchanged.

Stage px throughout (680×596, see SPEC §1). Same palette, fonts, Nixie tubes and label paints as SPEC.
Battery contract unchanged: 0 fps at rest; new screens are static frames; every animation is a short burst.

## Screens (swipe ← next, → previous; tap = next unless the screen uses taps)

`TODAY → RECENT → STREAK → WEEK → ALL-TIME → BADGES → CATS → OPEN → (TODAY)` (order and gestures: `UX-PASS.md`)

OPEN is last so it's one swipe right from Today; CATS is two. When the rear dims, it goes back to Today
(the doze face is always Today).

## 1. OPEN — open-PR status lights

Data: one extra `search(author:@me is:pr is:open archived:false sort:updated-desc, first: 50)` in the same
GraphQL request (cost stays 1). Per PR: `isDraft reviewDecision mergeable autoMergeRequest reviews(states:APPROVED){totalCount}
commits(last:1){…statusCheckRollup{state}}` + `issueCount` for the total.

Status (first match wins) → lamp:
| Status | Rule | Lamp | Text |
|---|---|---|---|
| DRAFT | isDraft | off (dark jewel) | DRAFT |
| FAILING | checks FAILURE/ERROR | red | CHECKS FAILED |
| CONFLICT | mergeable CONFLICTING | red | MERGE CONFLICT |
| CHANGES | reviewDecision CHANGES_REQUESTED | red | CHANGES REQUESTED |
| READY | (APPROVED, or no decision + ≥1 approval) and checks SUCCESS/none | green | READY TO MERGE / AUTO-MERGING |
| RUNNING | checks PENDING/EXPECTED | amber | CHECKS RUNNING |
| WAITING | otherwise | amber | WAITING ON REVIEW |

(`mergeable` is UNKNOWN for most PRs until GitHub computes it, so UNKNOWN counts as fine.)

Layout: left list like Recent (x 26–372, rows 86 px from y 64): jewel lamp Ø12 at (32, row+7), `REPO · #N` silk
at x 50, title 21 px below, status text right-aligned at x 372 on the first line. Sorted green → red → amber → off,
then most recently updated; top 5. Right: three counters of 2 SMALL tubes (x 557/608): `READY` (y 52), `WAITING`
(y 210), `NEEDS YOU` (y 368, argon), labels 24 px above with their jewel. Empty: `NO OPEN PRs`.
Tap a row: detail card (same pattern as Recent): status, `OPEN 2D 3H`, review decision, checks, auto-merge, branch.

Alert: when a poll shows a PR newly READY or newly red, and nothing else is playing (awake, not night), cut to
OPEN for 6 s with that row's jewel striking (flicker + flare), then back to Today.

## 2. STREAK — workday streak + daily goal

- **Streak**: consecutive days with ≥1 merged PR, counting back from today. Sat/Sun without merges are skipped
  (they never break it); today doesn't break it until it's over. History beyond the 7-day fetch comes from a
  once-a-day backfill (week-by-week `merged:` searches of `mergedAt` only, walking back until the streak breaks,
  max 52 weeks) into the persisted `daily` map (now kept 400 days).
- **Goal**: PRs per day, default **10** (the user's median active workday is ~14; 10 is met ~60 % of active days),
  set in Setup. Stored in prefs `settings` (survives account switches).

Layout: `WORKDAY STREAK` (26, 22); streak in 2 LIFE tubes (x 24/180, y 46; 3 tubes ≥ 100); right: `BEST` + 3 SMALL
tubes (y 56), `TODAY` + 2 SMALL tubes (y 214, the count today). Bottom: `TODAY'S GOAL · 7 / 10` label (26, 346), an
IN-13-style **bargraph tube** (glass capsule x 24–656, y 384–432) whose neon column fills `min(today/goal, 1)` with a
tick per PR of the goal; past the goal the column runs white-hot and the label reads `GOAL MET · +3`. Under it, 7 day
jewels Mon–Sun for this week: lit = merged that day, ring = goal met.

**Hitting the goal** bumps that merge's moment to at least tier L, and after the moment the screen cuts to STREAK
where the column surges to full and overdrives (≈ 3 s), then back to Today.

## 3. BADGES — achievements

Thresholds calibrated on the user's last 6 weeks so they're achievements, not daily freebies:

| Badge | Earned (once per day, unless noted) | Gas |
|---|---|---|
| NET NEGATIVE | a day's deletions > additions (dels > 0) | argon |
| EARLY BIRD | a merge 05:00–08:59 | neon |
| 10K DAY | ≥ 10,000 lines changed in a day (generated files excluded) | neon |
| FRIDAY SHIP | a merge on Friday from 17:00 | neon |
| SPEEDRUN | a PR opened → merged in under 1 minute | neon |
| GOAL MET | the daily goal reached | neon |
| ON A ROLL | the streak reaches 5 (once per streak run) | neon |
| CENTURY | all-time merged PRs passes a multiple of 100 (once per hundred) | neon |

Persisted (prefs `state`, per account): earned keys (`EARLY_BIRD:2026-10-26`, `CENTURY:500`, …), per badge count,
first + last date. First run awards silently from the 7-day window.

Layout: `BADGES · 5 OF 8` (26, 22); 4×2 grid of 158×236 cells from (24, 52). Each cell: the icon as a cathode wire
(locked: unlit ghost wire; earned: lit neon/argon glyph with glow), name (15 px silk), `×3`. Tap a badge: card with
the big icon, name, rule, `EARNED ×3`, `FIRST …`, `LAST …`; tap again to go back.

**Unlock**: after the merge moment (and the goal cut, if any), the screen cuts to BADGES and each new badge plays its
own ≈ 2.4 s animation in its cell (strike-in flicker → overdrive + halo → a badge-specific motion: sun rising, bolt
flash, flames licking, rings pulsing, digits rolling, etc.), then back to Today. Never at night or while dozing
(awarded silently).

## 4. CATS — the colony

One sleeping cat per PR merged in the rolling 7 days (same window as the 7-day bank). Size by the PR's tier
(S .62, M .78, L .95, XL 1.15 of the flyby cat), frosting colour by repo (pink, blue, mint, lemon). Piled from the
floor up, oldest at the bottom, brick-offset rows with jitter, some facing left; a few have a static `z`. More than
fit → everything shrinks; past 60, `+N`. Label `CAT COLONY · 23 THIS WEEK` (26, 22). Static: 0 fps.

Tap: the newest 16 wake and fly round the stage (rainbows, flaming butts, loop-the-loops), then glide back to their
spots and curl up (≈ 3 s, little puff on landing). Drag still summons the pet cat.

## 5. WEEK — the recap

Calendar week, Monday 00:00 → now (inside the 7-day window on any day). `THIS WEEK · MON 20 – SUN 26 OCT` (26, 22).
PR count in 2 LIFE tubes (x 24/180, y 46); `LINES` with the + and − banks exactly where Today has them; a strip of 7
day columns (y 346–420: letter, count, lit if merged, ring if goal met); then `BEST · REPO #N · +46 −55` and its title,
and `STREAK 6 · GOAL 4 / 5 DAYS · 3 BADGES`.

Entering plays the replay: banks blank, then day by day (350 ms each) the day lights and the tubes roll up to the
running totals, then the best-PR lines fade in. Tap replays it. **Auto-plays once a week** from Friday 17:00 (or on
Sat/Sun if missed) the first time the rear is awake and idle.

## 6. Cleaner line counts — generated files ignored

Per PR, lines in lockfiles (`package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `bun.lock(b)`, `Cargo.lock`,
`poetry.lock`, `Pipfile.lock`, `uv.lock`, `Gemfile.lock`, `composer.lock`, `go.sum`, `Podfile.lock`, `pubspec.lock`,
`mix.lock`, `flake.lock`, `gradle.lockfile`, `packages.lock.json`), snapshots (`__snapshots__/`, `*.snap`) and generated
code (`*.min.js|css`, `*.map`, `*.pb.go`, `*_pb2.py(i)`, `*.generated.*`, `*.g.dart`, `dist/`, `vendor/`,
`node_modules/`) are subtracted from additions/deletions everywhere (banks, tiers, badges). Checked once per PR (merged
PRs never change) with a `nodes(ids:)` `files` query for PRs not yet checked, cached in the snapshot. The Recent card
shows `IGNORED 2 GENERATED FILES · 12,034 LINES` when it applies.

## 7. Smart polling

`pollMs` = 45 s when an open PR is READY or has auto-merge on (a merge is likely soon); else 15 min from 23:00 to
07:00; else 2 min. Still only while Merged is visible and unfrozen.

## 8. Buzz on merge

A short vibration as a fresh merge is detected (S: one tick; M: two; L: three; XL: three + a long one), with
notification vibration attributes so silent mode / DND are respected. Not at night, not on double-tap replays. Also
fires when the rear is dozing (the moment itself is skipped then; double-tap replays it). Note: with the phone idle,
HyperOS freezes Merged, so it buzzes on the first poll after the phone (or rear) wakes.
